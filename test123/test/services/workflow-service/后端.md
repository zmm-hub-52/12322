# 后端（workflow-service 工作流 + 动态数据表单微服务）

## 1. 定位/背景

workflow-service 提供两件事：

1. **工作流配置化**：管理员用「节点 + 连线」可视化搭流程，发布时编译成 BPMN 2.0 部署给 Flowable，运行时完全由引擎驱动。
2. **动态数据表单**：字段库 + 节点字段配置，发布时展开成自包含 schema JSON 快照，前端据此渲染/校验。

## 2. 技术栈

| 项 | 选型 |
|---|---|
| 框架 | Spring Boot 4.0.8 |
| 工作流引擎 | Flowable 8.0.0（自动建表，异步执行器关闭） |
| ORM | MyBatis-Plus 3.5.15（逻辑删除 + 字段自动填充） |
| Excel | EasyExcel 4.0.3（动态表头、无模型读） |
| 数据库 | SQL Server（mssql-jdbc） |
| 其它 | Lombok / MapStruct / Jackson 3（tools.jackson） |

端口 8090；数据库 erp1（localhost:1433）。

## 4. 设计思路

### 4.1 配置化工作流：节点+连线 → BPMN → Flowable 驱动

- 前端画布产物是「节点 + 连线」两张表（process_node / process_link）。
- 发布时 BpmnGenerator 把它们编译成 BPMN 2.0 XML，经 RepositoryService 部署给 Flowable。
- 运行期（发起/提交/审批）完全由 Flowable 引擎路由，业务侧只存单据和轨迹。

### 4.2 node_key 三合一

    node_key = BPMN userTask/gateway id = 表单快照 key

零映射：引擎任务的 taskDefinitionKey 直接就是 nodeKey，据此直接取 schema、找节点、写轨迹。

### 4.3 版本快照隔离（改图不影响在途实例）

- process_def.version：每次发布 +1。
- 发布时生成 form_schema_snapshot：
  - snapshot_json：表单 schema（按 nodeKey 组织字段）。
  - graph_json：可执行图快照（节点 + 连线 + 处理人元数据）。
- process_instance 记录 formSchemaSnapshotId；运行期解析“下一节点/处理人/字段”**只读快照，不再查 process_node/process_link 活表**。

因此发布后继续编辑图（草稿）不会影响已运行实例。

### 4.4 处理人分配

- fixed：配置期指定 fixedAssignee。
- dynamic：上一环节选下一人。
- 引擎里每个用户任务写 flowable:assignee=assignee_<nodeKey>；发起时分配首层任务处理人，提交/审批时用 BFS 跨网关分配下一层任务处理人。

### 4.5 审批驳回

审批节点生成两条出线：批准线（${approved}）与驳回线（${!approved}）。驳回策略：

| 策略 | 目标 |
|---|---|
| back_prev 退回上一步 | 反向回溯到上一个用户任务（跳过网关），找不到则终止 |
| back_starter 驳回到第一个任务 | start 后的第一个业务节点 |
| terminate 终止流程 | 指向该节点专属的 terminate 结束事件 |

**并行分支内**（split..join 之间）驳回一律强制 terminate（一票否决），避免单支退回 + 另一支汇合等待造成卡死。

## 5. 主要表及作用

| 表 | 作用 |
|---|---|
| process_def | 流程定义：code / name / version / status / deploymentId / publishedTime |
| process_node | 流程节点：nodeKey / nodeName / nodeType / rejectStrategy / assigneeMode / fixedAssignee |
| process_link | 节点连线：fromNodeId / toNodeId / conditionJson / sortNo |
| node_form_field | 节点字段：nodeId / fieldKey / orderNo / mode / override（节点级覆盖 required/rule） |
| field_def | 字段库：fieldKey / fieldType / fieldRule(JSON) / required / description |
| form_schema_snapshot | 版本快照：snapshotJson（表单字段）+ graphJson（可执行图） |
| process_instance | 业务实例：processDefId / processDefVersion / formSchemaSnapshotId / flowableInstanceId / formData / status |
| process_record | 轨迹：actionType(start/submit/approve/reject) / nodeKey / executor / comment |
| dimension / dimension_category | 维表（维度 → 分类，字段即分类下的第三层） |
| sys_user / sys_role | 用户 / 角色（免密测试身份） |

关系：

    process_def 1─n process_node 1─n node_form_field n─1 field_def
    process_def 1─n process_link
    process_def 1─n form_schema_snapshot（每版本一份）
    process_def 1─n process_instance 1─n process_record
    process_instance ──▶ form_schema_snapshot（引用运行期快照）

另有 Flowable 引擎表（ACT_* / FLW_*）由引擎自动维护。

## 6. 核心类

### 6.1 ProcessConfigService（配置 + 发布）

- saveGraph(defId, GraphDto)：节点按 nodeKey upsert、连线全量重建 —— 前端画布落库。
- publish(defId)：version+1 → SchemaAssembler 生成表单快照 + buildGraphJson 生成图快照 → BpmnGenerator 编译 BPMN → Flowable deploy → 更新 process_def。
- validateParallelRules：发布前校验（固定处理人必填、并行分支内终止、汇合后 fixed、汇合后禁 back_prev）。
- getLatestSchema：取最新发布版本快照（发起页预览用）。

### 6.2 BpmnGenerator（画布 → BPMN XML）

- 节点：startEvent / endEvent / userTask / parallelGateway / exclusiveGateway。
- userTask：flowable:assignee="${assignee_<nodeKey>}"。
- 排他分叉：出边 conditionExpression（默认边无条件，放最后）。
- 审批节点：批准线 + 驳回线（按策略接目标），并总是生成 <nodeKey>_rejEnd terminate 结束事件兜底。
- 并行分支内：isInParallelBranch 反向回溯遇 parallelSplit 即判定，强制 terminate。

### 6.3 SchemaAssembler（配置 → schema JSON）

把 node_form_field + field_def 拼装成自包含 schema：

    { schemaVersion, nodes: { nodeKey: [ { key,label,type,mode,required,rule,description } ] } }

字段定义已展开，前端不自己 join。发布时生成全流程快照存 form_schema_snapshot；配置期预览时实时拼装。

### 6.4 ProcessRuntimeService（运行期）

- start：建业务实例 → firstUserTasks 写首层 assignee_<key> → startProcessInstanceByKey（最新版本）。
- submit / approve：taskService.complete + nextUserTasks 写下一层 assignee_<key>；审批额外写 approved 变量。
- getNodeSchema：按 taskId 定位当前任务（并行多任务不能按实例 singleResult），返回 fields + formData + nextNodes + finished。
- nextUserTasks / firstUserTasks：BFS 跨网关收集“第一层用户任务”（串行 1 个、并行多支）。
- updateStatusIfEnded：提交/审批后查引擎，无活动实例则同步 status/endTime。

### 6.5 ExcelImportService（批量导入 + 校验）

- EasyExcel 动态表头（表头=字段 key 一行），无模型读 Map<Integer,String> 按列序映射。
- parseAndValidate：预览校验报告（逐行 errors）。
- validateRow：必填（含条件必填）+ 类型（number/date）+ 规则（enum/codeRange/range/pattern/requiredWhen 内层约束/valueWhen）。
- matchCondition：条件求值（eq/neq/contains/isEmpty/isNotEmpty/gt/gte/lt/lte）。

### 6.6 动态表单规则校验（两处一致）

规则 rule 是 JSON，类型：

    enum(下拉) / codeRange(编码) / range(数值) / pattern(正则)
    requiredWhen(条件必填 + 可选内层取值约束)
    valueWhen(条件取值，命中第一条 case 时值必须等于 expect)

校验逻辑有两份实现，必须保持一致：

- 前端 approval-ui FormRenderer.validate()（单条发起/办理）。
- 后端 ExcelImportService.validateRow()（批量导入）。

SchemaAssembler 对 rule 原样透传，不解析。

## 7. 主要链路

### 7.1 发布

    前端画布 GraphDto
      → saveGraph（节点 upsert + 连线重建）
      → publish：
           SchemaAssembler → snapshot_json
           buildGraphJson  → graph_json
           BpmnGenerator   → bpmnXml
           Flowable deploy（key=code，version+1，deploymentId 记回 process_def）

### 7.2 发起

    start：
      取最新版本快照 → 建 process_instance → firstUserTasks 写 assignee_<key>
      → startProcessInstanceByKey(code, businessKey=实例id, vars)

### 7.3 办理

    前端 getNodeSchema（按 taskId）→ FormRenderer 渲染 + 校验
      → submit/approve：nextUserTasks 写下一层 assignee_<key>
      → taskService.complete → updateStatusIfEnded

### 7.4 Excel 导入

    下载模板（表头=start 字段 key）→ 上传 parseAndValidate（逐行校验）
      → 前端预览 → 逐行/全部 startExcelRow

## 8. 约定/坑

- **node_key 三合一**，不要破坏。
- **版本快照隔离**：运行期解析图/字段只读 form_schema_snapshot（snapshot_json + graph_json），不查活表。
- **并行约束**：分支内审批驳回只能 terminate；汇合后第一个任务必须 fixed；汇合后第一个审批禁 back_prev。
- **getNodeSchema 按 taskId 定位**：并行时一个实例多个活动任务，不能 processInstanceId + singleResult。
- **驳回线不能指向分叉/汇合网关**：指向分叉会死循环、指向并行分叉会破坏 fork 秒结束；back_prev 反向回溯到上一用户任务。
- **时间口径**：业务表用 LocalDateTime（本地时间）；Flowable 返回的 Date 对外前用 ZoneId.systemDefault() 转 LocalDateTime，避免按 UTC 序列化带 Z。
- **编译**：后端必须用 JDK21 javac（_java_tools/jdk-21.0.12.1+1/bin/javac.exe），因为 lombok 1.18.38 在 JBR JDK25 下静默失效；运行仍用 JBR java。
- **schema.sql 是唯一权威建库脚本**，后续表变更直接改它（并对现库 ALTER 同步）。
