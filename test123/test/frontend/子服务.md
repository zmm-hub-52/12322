# 子服务（workflow-admin 配置端 + approval-ui 使用端）

## 1. 定位/背景

两个子应用分工明确：

- **workflow-admin（配置端）**：管理员在这里“搭流程、配表单”。三个页面：流程配置（5 步向导）、表单配置、维表配置。
- **approval-ui（使用端）**：业务人员在这里“发起、待办、办理”。四个页面：发起、待办、办理、已完结。

两者通过**后端下发的 schema 快照**衔接：配置端决定“字段长什么样”，使用端只负责渲染和填值。

    ┌─────────────────┐       配置/发布       ┌──────────────────┐
    │  workflow-admin │ ───────────────────▶ │  workflow-service │
    │  (配置端)        │                      │  (后端)            │
    └─────────────────┘                      └────────┬─────────┘
                                                   │ schema 快照
    ┌─────────────────┐                            ▼
    │   approval-ui    │ ◀───────────────────────────┘
    │  (使用端)        │   按 schema 渲染动态表单
    └─────────────────┘

## 2. 技术栈

同主应用（Vue3 + TS + Vite + iX + vue-i18n）。差异点：

- 子应用各自在 main.ts 注册 iX 组件与图标、各自创建 router/pinia/i18n。
- 保活模式下无需做无界生命周期改造，但保留 __WUJIE_MOUNT/__WUJIE_UNMOUNT 为将来单例模式预留。

## 4. 配置端 workflow-admin

### 4.1 流程画布（FlowGraph）

**自绘 SVG 横向节点链 DAG**，不引 bpmn.js。能力：

- 节点：开始/结束（圆）、填写/审批（圆角矩形）、并行/排他分叉汇合（菱形）。
- 连线：贝塞尔 + 箭头 + 排他分支条件标签 + 中点「+」插入按钮。
- 交互：点击选中高亮（iX 主色 #006e93）、问题节点红框高亮、未配置字段角标。
- 布局：utils/graphLayout 分层布局。

### 4.2 流程配置向导（wizard，5 步）

1. 基本信息 → 2. 流程模式模板单选 → 3. 节点链列表式微调 → 4. 跳独立表单配置页 → 5. 确认发布总览。

- 原则：**约束式配置**，每步只暴露合法选项（模板起步、连线中点插入、并行分叉/汇合成对、发布前校验）。
- 审批节点弹层：驳回策略（退回上一步 / 驳回到第一个任务 / 终止流程）+ 处理人模式（fixed/dynamic）。
- 并行约束（与后端一致）：
  - 并行分支内审批节点驳回策略锁定为「终止流程」（一票否决）。
  - 并行汇合后第一个任务锁定「固定处理人」。
  - 并行汇合后第一个审批节点去掉「退回上一步」。
- 草稿随时保存（内存 store → 后端），已发布版本只读、改新草稿（后端 version+1）。

### 4.3 表单配置（form/index.vue）

上卡片 FlowGraph 选节点；下卡片左字段库 + 右已选字段行内设置：

- 展示方式 mode：editable / readonly / hidden。
- 必填 required。
- 字段规则 rule：由 RuleEditor 可视化编辑。

### 4.4 规则编辑器（RuleEditor）

规则 = 取值 + 校验二合一，可视化编辑、用户不手写 JSON。规则类型：

| 规则 | 作用 |
|---|---|
| enum 下拉选项 | 枚举值 |
| codeRange 编码范围 | 前缀 + 起止 + 位数 |
| range 数值范围 | min/max |
| pattern 正则 | 常用预设 + 自定义 |
| requiredWhen 条件必填 | 触发字段满足条件时本字段必填；可选附带一条取值约束（单条 enum/codeRange/range/pattern） |
| valueWhen 条件取值 | 命中第一条满足条件的 case 时，本字段必须等于 expect |

条件操作符：eq / neq / contains / isEmpty / isNotEmpty / gt / gte / lt / lte。

注意：requiredWhen / valueWhen 属于**节点级**规则（引用同表单其它字段），只在表单配置页出现；维表字段级不提供。

### 4.5 画布 → schema 保存链路

前端画布的内存草稿（nodes/links）保存时组装成 GraphDto 提交后端：

    GraphDto {
      nodes: [ { nodeKey, nodeName, nodeType, rejectStrategy, assigneeMode, fixedAssignee } ],
      links: [ { fromKey, toKey, condition, sortNo } ]
    }

    PUT /api/process/{defId}/graph  →  后端 saveGraph：
      - 节点按 nodeKey upsert（存在则更新、不存在则新增、缺失软删）
      - 连线全量重建（fromNodeId/toNodeId 由 nodeKey 映射为节点 id）

nodeKey 是“三合一”key：画布节点标识 = BPMN taskId = 表单快照 key，前后端零映射。

## 5. 使用端 approval-ui

### 5.1 动态表单 FormRenderer（核心）

按 schema 字段渲染 iX 表单，字段类型 → 组件映射：

| 字段类型/规则 | 渲染 |
|---|---|
| textarea | textarea |
| select（enum 规则） | IxSelect 下拉 |
| codeRange ≤ 50 条 | IxSelect editable 可输入下拉 |
| 其余 input/number/date/codeRange>50 | IxInput |

- mode：hidden 不渲染 / readonly 禁用 / editable 可编辑。
- required + 规则前端校验：validate() 逐字段校验，返回是否通过；页面提交前调用。
- 规则校验类型：enum / codeRange / range / pattern / requiredWhen(含内层取值约束) / valueWhen。
- 条件求值 matchCondition：eq / neq / contains / isEmpty / isNotEmpty / gt / gte / lt / lte。

FormRenderer 是受控组件：内部 model + sync/emit 双 watch（带 JSON 内容比较防回环）。

### 5.2 与 schema 联动

- **发起页**：fetchDefSchema(defId) → 取 start 节点字段 → FormRenderer 渲染发起表单。
- **办理页**：fetchNodeSchema(instanceId, taskId) → 返回当前节点 fields + 历史 formData + nodeKey/nodeName/nodeType + nextNodes + finished。
  - fields 来自该实例版本快照（旧实例不受改图影响）。
  - formData 按 fieldKey 跨节点累积，后续节点配同 fieldKey 即可看到前序数据。
  - nextNodes 供“下一处理人”选择（仅动态节点）。
- **提交/审批**：前端 validate() 通过后调 submitTask/approveTask；成功后回待办列表。

### 5.3 发起双模式

- 动态表单：单条发起。
- Excel 导入：下载模板 → 上传预览校验 → 逐行/全部发起。

## 6. 约定/坑

- **并行约束**前后端必须一致（前端锁定 UI，后端 publish 校验兜底）。
- **RuleEditor 双 watch**：派生值用 computed，仅一个 emit watch + 一个 sync watch（内容比较防 echo），避免回环。
- **条件规则仅节点级**：requiredWhen/valueWhen 需要“同表单字段”上下文，维表字段级不提供。
- **codeRange ≤ 50** 用 ix-select editable，>50 退化输入框。
- 三个应用 vite 均配 optimizeDeps: { force: true }。
