# 前端主应用（无界微前端宿主）

## 1. 定位/背景

主应用 **apps/main** 是整套微前端的**宿主壳**，本身不承载业务，只负责：

- 侧边菜单 + 顶栏（主题/语言/测试身份切换/退出）
- 多 Tab 管理（打开/切换/关闭子应用）
- 登录态（免密测试身份：token = platform-token-<username>）
- 主题（iX classic light/dark）与国际化（zh/en/de）的全局下发
- 无界子应用挂载、保活与销毁

业务能力由两个子应用提供：**workflow-admin**（配置端）、**approval-ui**（使用端），宿主通过 **props 函数引用** 向其下发实时能力。

## 2. 技术栈

| 项 | 选型 |
|---|---|
| 框架 | Vue 3.5 + TypeScript + Vite 7 |
| 包管理 | pnpm workspace（monorepo） |

| 国际化 | vue-i18n 11（zh / en / de） |

## 4. 无界微前端架构

### 4.1 挂载模型

    apps/main（主应用）
      │  startApp(alive)
      ├──▶ workflow-admin（配置端）
      └──▶ approval-ui（使用端）
      每个子应用通过 props 函数引用 取实时能力；主应用与子应用之间用 wujie bus 广播主题/语言/事件。

- **保活模式 alive: true**：子应用切走不销毁，实例驻留各自容器，切回热插拔。
- **容器模型**：DefaultLayout 为每个打开的 Tab 渲染一个容器 div（content-pane--app），用 v-show 切换显隐；无界实例挂进各自容器。
- **路由同步 sync: true**：子应用路由同步到主应用 URL，刷新/前进后退不丢。

### 4.2 实例命名（关键）

保活模式下，同一个无界 name 改 url 无法跳不同路由，因此**一个 Tab 对应一个独立实例**：

    name = ${appName}-${id}    // 例如 approval-xxx，唯一

即「一个子应用的多个菜单项 = 多个独立实例」，由 Tab 自己管生命周期。

### 4.3 props 契约（替代 window 桥）

主应用通过 props 向子应用下发**数据快照 + 函数引用**，子应用每次调用函数即取最新值（避免 window 全局桥的脏数据）：

| 名称 | 类型 | 用途 |
|---|---|---|
| user | 快照 | 当前用户信息 |
| getToken() | 函数 | 实时取 token |
| getUser() | 函数 | 实时取用户 |
| getTheme() | 函数 | 实时取主题 |
| jump(route) | 函数 | 子应用跳转 |
| showToast / showMessage | 函数 | 全局反馈（iX toast/message，避免 iframe 边界裁剪） |

子应用 HTTP 由 SDK 的 createSubAppHttp() 创建：token 从 props.getToken() 实时取，401 经 bus 上报主应用统一处理。

## 5. Tab 组件设计（TabManager）

packages/tab-manager/src/TabManager.ts 是纯 TS、框架无关的多 Tab + 实例管理器，核心职责：

- **Tab 元数据**：打开顺序、标题、url、激活态；持久化到 sessionStorage（key platform-tabs），刷新后恢复。
- **实例运行记录**：每个 name 一个 record（status / el / destroy / idleTimer / lastActiveAt）。
- **唯一实例名**：${appName}-${id}。
- **保活**：alive: true，切换只 v-show，不销毁。
- **空闲超时**：切走后台开始计时，默认 10 分钟未激活 → 销毁实例（Tab 保留，下次激活重挂）。
- **数量兜底（LRU）**：存活实例超过 maxAlive（默认 6）时，按 lastActiveAt 淘汰最早打开的非激活实例。
- **幂等挂载**：mountTab 对 loading/loaded 直接跳过；初始状态必须是 idle（曾因初始 loading 被幂等守卫误拦，导致首次挂不上）。

关键生命周期：

    openTab   → 建 Tab + 激活（startApp 在拿到容器 el 后调 mountTab）
    mountTab  → startApp({ name, url, el, alive, sync, props })
    activate  → 停前一个后台计时 / 清当前计时
    closeTab  → destroyApp(name) + 激活相邻 Tab
    超时/淘汰 → destroyInstance（只销毁实例，Tab 保留）

## 6. iX 风格统一

### 6.1 主题源

packages/ui-theme/src/theme.css 是**单一主题源**，主应用与每个子应用各自引入：

    @import '@siemens/ix/dist/siemens-ix/siemens-ix.css';
    @import './fonts.css';

    [data-ix-theme='classic'] {
      --brand-primary: var(--theme-color-primary);
      --brand-text: var(--theme-color-std-text);
      /* --brand-* 别名 → iX --theme-* token */
    }
    [data-ix-theme='classic'][data-ix-color-schema='dark'] {
      --brand-bg: #17191c;
      /* 深色仅覆盖 iX 没有的 solid 背景 */
    }

- 主题切换靠 <html> 上的 data-ix-theme="classic" + data-ix-color-schema="light|dark"，主色 #006e93。
- 主应用 theme store 切换后经 bus 广播 THEME_CHANGE；locale store 广播 LOCALE_CHANGE；子应用监听同步。

### 6.2 组件使用约定

| 场景 | 用啥 |
|---|---|
| 布局/结构（application/menu/icon 等） | 原生 <ix-*> 标签，main.ts 里 defineCustomElements() 注册 |
| 表单/交互（按钮/输入/下拉/开关/反馈） | @siemens/ix-vue 的 PascalCase 组件（IxButton/IxInput/IxSelect/IxToggle + showToast/showMessage） |

Vite 侧：isCustomElement: tag => tag.startsWith('ix-')。

## 7. 约定/坑

- **无界 shadow DOM 的 :root**：匹配的是 shadow host（<wujie-app>），不是子应用 <html>。所以品牌别名用**纯属性选择器** [data-ix-theme='classic']，不用 :root。
- **iX 5.2.1 双 loader 同名**：@siemens/ix/loader 和 @siemens/ix-icons/loader 都导出 defineCustomElements（不是 defineIxIcons）。
- **wujie 2.x destroyApp 返回 Promise**。
- **子应用滚动两套方案并存**：
  - approval-ui：宿主容器滚动 + 子应用顶栏 sticky（绕开 shadow 高度链）。
  - workflow-admin：html/body/#app 高度链 + flex 内部滚动。
  不要混用。
- **props 传函数引用**，实时取最新值；不要缓存快照。
- 三个应用 vite 均配 optimizeDeps: { force: true }，启动略慢但避免预构建缓存问题。
